DURATION (DOI) PATH - why the reader list is 8, not 14
  At 0xC6244 the code loads r15[289] = 0x1DF054 and builds six pointers:
    +0x1A  -> 0x1DF06E Dur00     +0x10E -> 0x1DF162 Dur01
    +0x390 -> 0x1DF3E4 Dur02     +0x612 -> 0x1DF666 Dur03
    +0x894 -> 0x1DF8E8 Dur04     +0xB16 -> 0x1DFB6A Dur05
  stored as a pointer array on the stack. The Duration maps are therefore NOT
  passed to 0xF94DC and never match a reader header; they are selected by
  InjVlv_numMI1_CUR (0x1DF062), a 6-point curve indexed by SOI angle.
  Clone base 0x1F4000 (slot1) / 0x1F6000 (slot2) maps 0x1DF02E, so the six
  computed pointers land in the slot's copy. Slot table at 0x1F3F00.

PEDAL GATE (present since before v2.0.1, unchanged in v2.1.0)
  First check in the TL thunk 0x1FC000:
    lha    r12,-27180(r13)   ; 0x7F95C4  signed, so negatives sign-extend
    cmplwi r12,0xC8          ; 200
    bgt    original code     ; unsigned compare: negative -> huge -> blocked
  Map switching is therefore only possible with the pedal released.
  0x7F95C4 SCALE IS UNRESOLVED:
    0..10000 (0.01 %)  -> 200 = 2.00 %   (foot off)
    0..250   (%)       -> 200 = 80 %     (nearly full throttle)
  VCDS MB 054/062 shows accelerator pedal; idle vs full throttle settles it.
  CORRECTION: 0x064790 (sth 0x7F95C4) is a RESTORE, not the producer - the same
  function reads it at 0x064428 and stashes it. 0x0FEBC0 is a descriptor job
  submitter (descriptors 0x445CC, type byte 0x4BCC2, data base 0x7FEA04, ring
  0x7FF490 size 4 from 0x44791), not a scaler. No other writer exists (r13-relative
  or absolute). The value almost certainly arrives via that descriptor/transfer
  layer from the ADC. Weak evidence for 0..10000: cmpwi 0x2710 at 0x661B38,
  0x661D30, 0x66950, 0x66988, 0x669B8.
  v2.1.0: the threshold is now a parameter, MAPS_PEDAL_MAX at 0x1EA7CC (u16),
  default 0x0000 = gate disabled. Non-zero blocks switching above it; negative
  pedal is always blocked. WinOLS factor 0.1 gives a 0-100 % display.

PEDAL PROVENANCE - WHAT WAS RULED OUT
  1. FUN_000febc0 cannot reach 0x7F95C4: iVar4 = 0x7FEA04 + u16_offset + param_2,
     so targets are 0x7FEA04..0x80EA03. Pedal is 0x5440 BELOW the base.
  2. 0x4BCA4..0x4BD40 is DATA, not missed code: entropy 4.40-4.88 vs 5.17 for code.
     0x4BCC2 is a type registry with handlers at 0x4BCDC (0x0010F934),
     0x4BCE0 (0x0010FA20), 0x4BCE4 (0x0022FFF0).
  3. FUN_00004cbc stages code to 0x7FF000 / 0x7F8000 and runs it via a RAM
     trampoline; status at 0x7FEF5D..0x7FEF60. FUN_000febc0's _DAT_007fefd4 == 2
     is in that same block => boot/programming state, not ADC.
  4. 0x064790 is a RESTORE of the value read at 0x064428.
  Remaining: QADC/TPU layer. FUN_00004cbc drives 0x6FC004, 0x700004, 0x704800,
  0x704A00, 0x704C00, 0x704E00, 0x706806, 0x706816, 0x702000 - all outside the
  2 MB flash. Needs the MPC562 peripheral map.
